## Development history

The remaining documents record past milestones, experiments, issue plans, and design decisions. Names such as M1, M2, V2, V3.0, and `build N` are internal development checkpoints, not current public release numbers. References to `codex/v2` describe the branch used at the time; it was later merged into `main` and deleted.

In particular, the files under `docs/issues/`, `docs/roadmaps/`, and files beginning with `m1-`, `m2-`, or `v2-` should be read as historical project memory unless the current-state audit links to a specific section. They are intentionally retained to explain why features were added, changed, or removed.
